# 家庭记账（FamilyAcount）

一个控制台版的记账小工具，也是我学 Go 时用来练「两种编程范式」的练习题：**同一套需求写了两遍**，一遍面向对象、一遍面向过程，放在两个互不相干的子目录里，好对照着看。

- `对象demo` —— 面向对象版，账户状态收进结构体，每个功能一个方法。
- `过程demo` —— 面向过程版，所有逻辑写在一个 `main` 里，靠 `for` + `switch` 分发。

两版的菜单、提示语、明细表格式刻意保持一致，所以你可以把两边对着读，看的只是「组织代码的思路」差异。

## 功能

程序启动后是一个循环菜单：

| 选项 | 作用 |
| --- | --- |
| 1. 收支明细 | 按「收支 / 账户金额 / 收支金额 / 说明」四列打印已登记的每一笔；一笔都还没有时提示先登记 |
| 2. 登记收入 | 输入金额和说明，账户余额增加，明细追加一行「收入」 |
| 3. 登记支出 | 输入金额和说明，账户余额减少，明细追加一行「支出」 |
| 4. 退出系统 | 用 `Y/N` 再确认一次：`Y` 才退出，`N` 提示「退出失败！」并回到菜单 |

规则很简单：金额输成文字会提示「输入错误，请重新输入！」并放弃这一笔；明细表用制表符对齐，账户金额一列显示的是每笔之后的余额。

## 运行

需要 Go 1.27 或更高版本。只用了标准库（`fmt`），没有第三方依赖。

两个子目录各自是一个独立的 Go module，所以要分别进去运行：

```bash
# 面向对象版
cd 对象demo
go run ./main
```

```bash
# 面向过程版
cd 过程demo
go run .
```

程序全程需要键盘输入，请在能打字的地方运行（IDE 的集成终端、Windows Terminal 都行）；在那种「只显示输出、收不到输入」的运行窗口里跑，第一次要输入时就会卡住。

## 目录结构

```
FamilyAcount/
├── 对象demo/                面向对象版
│   ├── go.mod               模块 demo（独立 module）
│   ├── utils/utils.go       账户结构体和它的方法：菜单、明细、登记收入、登记支出、退出
│   └── main/面向对象编程.go  入口，只有一行调用
└── 过程demo/                面向过程版
    ├── go.mod               模块 demo（独立 module）
    └── 面向过程编程.go        菜单、记账、明细全在一个文件里
```

## 两版是怎么写的

### 面向对象（`对象demo`）

先定义账户本身：余额、收支金额、说明、明细、当前选择的菜单项、有没有记录、要不要退出，全是 `FamilyAccount` 的字段；构造用 `NewFamilyAccount()` 给明细加上表头。然后每个菜单项对应一个方法：

- `MainMenu()` —— 打印菜单、读选项、分发
- `checkdetail()` —— 打印明细
- `incount()` / `outcount()` —— 登记收入 / 支出
- `endexe()` —— 退出确认

方法都挂在指针接收者上，改的是结构体里的同一份状态，不用把数据传来传去。入口文件里只有一句 `utils.NewFamilyAccount().MainMenu()`。

好处是状态集中、职责分明：以后想加个「查询某笔记录」或者「导出明细」，在 `utils` 里加方法就行，入口不用动。

### 面向过程（`过程demo`）

反过来，所有东西都摊在一个文件里：外层一个死循环打印菜单，读进选项交给 `switch` 分发；余额、收入、支出、说明是 `main` 里的局部变量，明细则是一个字符串 `detail`，每记一笔就往后拼一行。要不要退出用一个包级变量当下的「开关」控制。

好处是流程一眼能从第一行看到最后一行，不用跳来跳去，特别适合刚开始写这种菜单式小程序时理顺逻辑；代价是功能一多，这个 `main` 会越来越长。

### 对照

| | 对象demo | 过程demo |
| --- | --- | --- |
| 状态放哪 | 结构体字段，随对象走 | `main` 的局部变量（退出标志提到包级） |
| 功能怎么组织 | 一个方法管一件事，入口只有一行 | 全部写在 `switch` 的各个 `case` 里 |
| 想加功能 | 在 `utils` 里加方法 | 继续往 `main` 里塞 |
| 适合的场景 | 功能会不断变多 | 快速把逻辑跑通、验证想法 |
